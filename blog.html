How I Built a Trading Execution System

This project started as an attempt to understand how orders are processed and executed in trading systems. Instead of focusing on theory, I wanted to simulate how orders flow through a system and how matching actually works.

Problem

The goal was to design a simplified system where buy and sell orders could be processed and matched. I wanted to understand how systems handle order priority, partial fills, and consistency.

Design

The system takes in orders and stores them in separate structures for buys and sells. Orders are matched based on price and arrival priority.

If a match is found, the system executes the trade and updates the remaining quantity. If not, the order is stored until a matching order arrives.

Challenges

One of the main challenges was handling partial matches correctly. Another challenge was ensuring that the system always processes orders in the correct priority order.

Learnings

This project helped me understand that trading systems are less about complex algorithms and more about handling edge cases and ensuring consistency.

It also made me appreciate how important latency and system design are in real-world trading environments.
